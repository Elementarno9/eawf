Each iter (P30-I01..I19, where `I<NN>` is an iter and `W<NN>` a wave) already passed its own fresh-context close audit; this pass audits the **phase as one unit** to catch cross-iter drift, regressions one iter introduced into another's surface, and idle contracts that survived — the slices a per-iter audit cannot see.

### Real defects found — all fixed before close [1]

- **Doctor check-count drift (J1, real, suite-reddening).** `tests/unit/test_doctor_mcp_drift.py` pinned `len(run_all()) == 8`, but the doctor returns exactly 7 checks — the eighth was the seal-capability row, removed when the raster seal stack was retired (I19-W11/W12). Its sibling `test_doctor_checks.py` already asserted 7; this drift-twin was missed, so the full suite failed on a real (non-flaky) error. Fixed in **W13** (assertion 8 -> 7).
- **The one idle contract that escaped the gate (J2).** The dedicated daemon RPCs `track.add` / `track.switch` were registered but never called — the CLI `track add` / `track switch` verbs run the in-process write path — so the RPCs never fired and their docstrings falsely claimed the CLI routed to them. The feature works live via the in-process transition; only the redundant daemon RPC seam was idle. Per operator decision, fixed in **W14** by retiring the orphaned RPCs (apply functions, params/result models, the `check_track_rpc_wired` idle-gate check, and their tests), keeping `track.sync` and the phase-track-tag binding. The rule-4 daemon-proxy routing is backlogged for when a real consumer exists.
- **Latent `mypy` errors masked by the incremental cache (J1-adjacent).** A no-cache `mypy src/` surfaced three type errors the cached baseline run reported clean: `fleet.py:2101` (`no-any-return`), `fleet.py:3622` (a `str | None` passed where `str` is required), and `evidence_hypothesis.py:187` (indexing a `dict | None`). Fixed in **W15** (typed local, an early `ADVISORY` guard matching its sibling, an invariant assert); `mypy src/` is now genuinely clean (691 files, 0 errors).

### Polish (W15)

The four stale comments in `tui/app.py` that attributed the startup key-leak trigger to "the seal Image widget's transmit" were refreshed — the seal is ASCII text after I19-W12 and transmits no graphics-protocol image; the interactive-ready gate is unchanged sound defense against any startup terminal capability / Device-Attributes probe reply. A bounded `eawf:polisher` sweep over all 241 P30-touched `src/eawf/` files found **zero** naming / log-key / error-phrasing / docstring violations to fix — confirming the diff is convention-clean.

### Deferred (non-blocking, recorded as backlog) [2]

- `docs/architecture/state-model.md` is stale across ~17 spots (still describes the `Subproject` entity and schema literal `"1.0"`; the entity is `Track` and the schema is `1.12`). A full refresh is its own focused doc task; a partial rename would be more confusing than none.
