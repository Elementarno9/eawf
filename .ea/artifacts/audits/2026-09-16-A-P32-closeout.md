# P32 closeout audit

## Summary

Phase P32 delivered the 0.7.0.dev2 offline-migration checkpoint in one iter of fifty-three waves. The epoch-2 cutover exists end to end: a read-only plan that seals a strict manifest, a journaled twelve-stage apply with an atomic generation select, recovery and rollback, and a rehearsal over ten corpora that crashes the apply at each of its eleven durable writes. The version reads 0.7.0.dev2 and the changelog section names the migration limits. The out-of-band 0.7.0.dev1 publication is recorded through a typed adoption and stands at `partially_released` with no approval attached.

A fresh-context audit returned **major** against the branch as it stood. Both major findings were repaired inside the phase before close, so the recorded verdict is **minor**: what remains is filed as backlog with its evidence. The CI-mirror gauntlet on the final head reads: pre-commit, deptry and mypy are clean; the parallel coverage leg passes 18,594 tests, failing only a help-text check against a codex CLI installed on the auditing machine, which skips in CI, and a coverage-gate self-test that read a stale local report and passes once the report is regenerated; the 421 TUI snapshot tests and the perf and metrics suites pass; overall coverage holds at 89% and every per-package gate passes, the state package at 99.74% line and 98.70% branch.

## What the audit found

**The receipt floor and the deterministic tier never ran for most waves in this repository.** W43 set out to stop mechanical waves closing without running their gates, and its tests passed. They all modelled a profile with no UI bands. This repository enables the band-scoped `quality` profile, whose resolver narrows a mechanical wave outside the bands to `enforce=False`; the close gate returned on that narrowed flag before W43's tier choice and its receipt floor. W08, W13, W20, W26, W41, W42, W43, W45 and W46 closed with required gates and zero receipts, three of them after W43 landed. W48 repairs it: the gate now returns early only when the merged profile enforces nothing, and the close tests run under both profile shapes. Restoring the old return reds exactly the six band-scoped cases.

**Seven recorded gates could never have passed as written.** Of 117 unique command gates replayed on the phase head, 110 passed. W20's two gates named a test directory a later wave retired, W26's three named files that never existed, and W41 and W42 each selected a test name nothing carries, so pytest exited 5. Because their waves closed without receipts, none of them had run at close. All seven were repointed with the closed-wave argv repair and now pass.

## What the ship pass repaired

The phase PR's CI could not go green, and neither failure was the runner's. The ubuntu coverage leg died twice at 31%: the `sysmon` coverage core keeps every code object it sees, and each in-process CLI invocation rebuilt the command tree and evaluated about six thousand annotations. A full four-worker coverage run retained 14.0 GB on this branch against 12.3 GB on `main`, past the 16 GB runner. W47 builds each tree once per worker, which retains about 0.17 GB. The two twice-green reds were test races, one per run, each reproduced under load and fixed test-side: a refused close left its event loop before the workspace cleanup started, and the feed test raced the application's own daemon probe (41 of 500 loaded runs failed before, 0 of 500 after).

With the leg surviving, the per-package coverage gate would have been next: the state package measured 93.78% branch coverage against a 95% gate, all of it this phase's epoch-2 validators with no error-path tests. W50 covers them, and the package now measures 98.70%.

The PR review of the ship pass then reproduced a refusal W48 had widened: a sampled mechanical wave with an attested criterion that carries a gate, or with only advisory gates, fell through to an auditor verdict no mechanical close ever writes. W51 scores only the criteria the receipt floor obliges, which is what the profile promises such a wave.

The macOS leg then drifted two TUI goldens in consecutive runs. The snapshot harness forced the footer heartbeat lit through a lookup that, after a mode switch, returns the home screen's heartbeat rather than the captured screen's, so every mode-screen golden rode the pulse phase. W52 lights the active screen's heartbeat.

The next twice-green run tripped the CLI cold-import ceiling, 777 ms against 750 ms, for an import that takes about 300 ms on an idle host: the budget ran inside the parallel worker pool. W53 moves both wall-clock budget suites to the serial perf step, with a placement check.

That run also caught two test readers racing their writers: W52's own mode-screen case, whose live heartbeat pulse re-lit the dot before its first capture, and the portalock heartbeat test, which parsed the lockfile while the ticker rewrote it in place. W54 stills the pulse in the one and reads across the rewrite window in the other.

## What did not land

W21 was scoped to cut, publish and observe dev2 to BAKED. Approving the live record refuses on an unmerged branch because the ancestry signal is red, and BAKED needs the tag pushed to live registries after the merge. The operator split the wave: W21 closes on the three criteria met on this branch, and the BAKED observation moves verbatim to P33-I01-W01, which leads P33 because dev3 opens only from a terminal dev2. Nothing was published and no tag was pushed.

## Verification integrity

Twenty-four closed waves carry a pinned commit that is not an ancestor of the phase head. Each has a landed commit with the same subject and trailer, and outside `.ea/` the pinned and landed diffs are identical; the drift comes from folding close bookkeeping into the wave commit by amend. A rebase merge restales every pin, so the repin belongs after the merge. The receiptless closes above cannot be re-receipted: no verb re-runs a closed wave's gates, which is backlog B134.
