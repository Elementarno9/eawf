# P35-I01 evaluation audit

## Summary

Iter P35-I01 set out to land planning, identity and the plan transaction: publish and bake `0.7.0.dev3`, run the plan lenses at submit, grade criterion grounding, promote measured contracts, type the research Campaign's budget and stop rules, separate auto-resolved questions and pauses from answers, supersede conflicting approval answers, qualify workspace rows, give the native verbs a CLI, wire `submit_report` and `/integrate seal`, run the post-merge release steps as one pipeline, and clear the P34 test-only leftovers. It ran fifteen waves.

The fresh-context audit returns **major**. Every spec gate is green at the landed head (all fifteen gate files plus their neighbouring suites, 1,669 tests), and the release, identity, CLI and budget work holds. But four high findings are unrepaired: an accepted-risk criterion reaches APPROVED on a Decision reference nobody resolves, the `submit_evidence` handler writes `state.json` around the locked, atomic, leak-refusing write chokepoint, and two research-campaign mechanisms (the evidence budget and the contradiction halt) have no production path at all. The last two are in the operator's known-gap list, but the operator's standing rule is no idle substrate, so they count as open, not waived.

During the audit the branch was rebased with two fixups: W05's schema change had shifted seven migration-rehearsal goldens without refreshing them, and W06 added an integration test module whose basename collided with the unit gate file. Both are repaired at the landed head and are recorded here as low findings.

## What the audit found

**Release work holds.** W01's committed stores hold `REL-0.7.0.dev3` BAKED with four observed targets and a train advance to dev4, and the `release.candidate` fix for membership rungs is exercised by a daemon-method test. W14's pipeline refuses before any tag push without the publish flag, resumes after an interrupted candidate step without repeating a step, reaches BAKED against fake adapters and calls `resolve_trailer_repins`, which gives that function its first production caller. The W01 gate test asserts the train is still on dev4, so it will red on the next legitimate advance.

**Identity, CLI and budget work holds, with gaps in what reaches production.** W11 refuses a cross-workspace membership update with no registry write, but `qualify_rows` is the one new idle function in the iter: no aggregated read calls it. W12 registers one command per native create, plan, seal and submit RPC, but refusals exit 3 (the repo's STATE_CONFLICT convention), not the spec's 4, and the milestone create-then-activate criterion is proved only against a fake client. W15 forwards `/dispatch --budget` into the capsule's `token_budget`, which the daemon seals and meters, and removes the other three P34 leftovers; the idle report drops from 221 to 218 functions over the iter.

**The planning lenses run at submit, but the grounding refusal has two holes.** W02 to W04 register all lenses in the runner that `validate_plan_proposal` calls, and W05 refuses VALIDATED to APPROVED while an acceptance-mapped criterion is assumed. An accepted-risk criterion, however, only needs a non-empty Decision reference: nothing resolves it, so `DEC-bogus` approves. No current plan producer fills the new lens inputs (source atoms, write claims, grounding), and grounding defaults to assumed, so every plan from today's producers is refused at approval until a producer grades it. Several gate tests are weaker than their criteria (the zero-rows assertion, the verb-to-tier mapping, the shuffle that only reorders dict keys).

**The research-campaign waves type more than the runtime uses.** W07's `evidence_budget` is never written or read by a source path, and its transition check sits behind an ACTIVE-only guard that makes it unreachable. W08's contradiction halt can never fire live because `reconcile_round_claims` writes only OPEN claims and `build_bound_round_runner` has no caller. W09's AUTO_RESOLVED status is produced, but the research board never shows the count, SEALED is never set, and `drop_reason` is never written.

**The report and approval surfaces are wired but do not record everything they promise.** W13's `SUBMIT_REPORT` handler exists and `/integrate seal` no longer stops on `candidate_report_unbound`, but the handler records nothing, the report digest and verdict still have no producer, and the canary walk still binds the report by a direct verb call. W10 supersedes a conflicting answer instead of rejecting it, but builds the losing answer's disposition row and throws it away, and a duplicate answer over RPC returns no receipt.
