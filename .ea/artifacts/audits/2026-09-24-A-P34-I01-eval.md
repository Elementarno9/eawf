# P34-I01 evaluation audit

## Summary

Iter P34-I01 set out to cut the `0.7.0.dev3` native canary checkpoint: repair the evidence the train rests on, close the epoch-2 correctness gaps P33 left, give the native producer chain real producers from create to acceptance, open the epoch-2 console from `eawf tui`, and walk one canary Milestone to acceptance. It ran forty-eight waves - thirty-nine planned and nine appended when the work, the live console test, the iter-close suite and this audit each surfaced a gap no planned wave owned.

The fresh-context audit first returned **major** [R1]. The hygiene, gate and release-preparation claims held, but the headline claim did not: a worker's MCP-submitted candidate could not be integrated, the Claude budget meter under-counted, the daemon-down state writers skipped the leak refusal, and about thirty `EAWF_` control variables leaked into the config env layer. The operator chose to repair all four inside the iter, which waves W45 to W48 did, and every medium and low finding is filed with evidence as B165 to B176. Under the rule P32 and P33 used - repaired in phase, or filed with evidence - the recorded verdict is **minor**.

One planned outcome moved by decision rather than failure. `REL-0.7.0.dev3` cannot reach APPROVED before it is published, because CANDIDATE freezes its manifest from publication receipts that only a tag push from `main` produces, and tags come only from `main`. The operator ruled on 2026-09-24 to move the create, candidate, receipts and approval into `P35-I01-W01` after the fast-forward landing; W39 proves the pre-publication half, and B163 files the root cause so that no future rung slips a phase the same way.

## What the audit found

**The producer chain now reaches acceptance, on a disposable tree and with stated seams.** Native create transitions (W15), valid skill principals (W16), the acceptance PendingAction (W17), request assembly (W18), the semantic submit handler (W19), the in-flight meter and the per-Run MCP stream (W20, W21) and a daemon-owned git integration workspace (W40) let W37 walk one canary Milestone to COMPLETED through the dispatch, integrate and verify skills. The walk runs on a stand-in launcher, and its creates, report bind, seal and accept are direct verb calls; its evidence file records each step's path. B169 and B170 carry the verbs that still have no supported surface.

**Four high findings, all repaired in the iter.** The Claude adapter relayed per-call usage into a meter that keeps the largest reading, so a Run was metered at its biggest call (W45 now relays the running sum). The semantic submit handler wrote no commit pin, so integrate refused every MCP-submitted candidate (W46 routes it through the same pin as the RPC path). `commit_mutation` and the other state writers reached when the daemon is down wrote `state.json` with no leak refusal (W47 puts the refusal in the shared write chokepoint and adds a census). The config env layer read about thirty control variables as config keys, so `EAWF_COAUTHOR_MODE=disabled` made `config validate` exit 2 (W48 reserves every one and adds a census that reds on a new unreserved read).

**Three product bugs surfaced only when the work was exercised end to end.** W38's live console test found that the Attention route refused its whole read once an acceptance question opened and that a Milestone compacted at a terminal status vanished from every native route (W42 repaired both). The same test's close gate exposed `EAWF_GATE_FILES` leaking into the settings route. The iter-close suite found that a refactor had moved the `runtime.capture` method registration onto a helper, so every call to the method would have failed (W43 repaired it and added a test through the real dispatch path).

**Evidence hygiene holds.** `eawf wave verify-commits` reconciles every closed wave with zero drift after W02 re-pinned 689 pins and acknowledged three ambiguous rows by name; W03 archived and pruned 76 local branches with drift unchanged; W04 lands phases by fast-forward with a trailer-and-patch-id repin as the fallback, whose production caller is still missing (B167).

**The four gates P33 found unable to fail can now fail.** W08 rewired the idle-contract row counter, the helpers-wired check and the asserting-test contract onto AST references, and the coverage gate refuses a stale report; W31 adds a rule that reds a console app with no reachable launcher. The coverage freshness probe still checks only that the helper is named (B168).
