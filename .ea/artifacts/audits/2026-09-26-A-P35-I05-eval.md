# P35-I05 evaluation audit

## Summary

Iter P35-I05 is titled "Cut 0.7.0.dev4 as a native-canary checkpoint". Decision D70 opened it: the product-canary rung needs this repository cut over to epoch 2, which D69 moved to P36, so dev4 is cut as a second native-canary checkpoint and the product canary becomes `0.7.0.dev5` [1]. The iter shipped four waves: W01 rebinds the train (`b0f55499`), W02 keys the canary evidence by release and records the dev4 export (`6dfc2f1a`), W03 bumps the version and writes the changelog section (`77bfeeeb`), and W04 lets the release pipeline's evidence commit pass the commit lint (`7351ff95`).

This fresh-context audit returns **minor**. Every wave gate is green, and nothing outside the gates broke. It made two minor findings: a wrong schema number in the dev4 changelog Migration note, and a train-length pin that only the iter-close full suite reached. The W05 polish wave fixed both.

## What the audit found

**The train carries eight rungs.** dev3 and dev4 run `native_canary`, dev5 runs `product_canary` and has no authored configuration, and `checkpoint_release_config("0.7.0.dev4")` builds four targets with the dev4 membership reference [2].

**Each native-canary rung reads its own evidence.** `CANARY_EVIDENCE_DIRS` maps each release key to a dated directory. An export that names another release is refused, and an unmapped key reads as absent evidence [3]. `committed_membership_refs` now raises on a mismatch instead of returning nothing. Both callers handle that: the tag-time config builder and the daemon's membership check. Their tests gave 203 passed and 7 skipped.

**The dev4 evidence brief is honest.** It states that the certification is carried forward from the dev3 export rather than re-probed, keeps that record's timestamps and its 2026-12-17 expiry, and names the freshly recorded walk as the source of the membership reference [4]. A scan for paths, emails and private addresses found nothing.

**The changelog claims hold except one.** The audit checked five bullets against the source: the eight-rung train, `eawf migrate epoch2`, `eawf release pipeline`, the render-over-cap failure and the release-keyed evidence. All five hold. The Migration note said the schema is "unchanged at 1.19". The latest epoch-1 schema has been 1.20 since 0.6.4, and it was 1.20 at the dev3 tag too; only this repository's own state file is still at 1.19.

**The lint change is narrow.** `_state_strays` admits `.ea/artifacts/evidence/**`, and `.pre-commit-config.yaml` only beside `.secrets.baseline`. `_is_state_only_path` is unchanged, so fold detection and the wave-cap exemption are not affected [5].
