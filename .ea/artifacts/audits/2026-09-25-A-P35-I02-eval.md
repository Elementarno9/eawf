# P35-I02 evaluation audit

## Summary

Iter P35-I02 set out to compile the rule graph and render the steering projections: load `.ea/rules.yaml` into strict frozen records, compile one effective graph with one owner per obligation, select builtin modules and render the module index, compose builtin, workspace and repository layers, author this repository's rules, render the project card and the policy projection in one transaction, emit the import shim, module views and role carriers, certify host facts per runtime, compile the conduct obligations and fire the practice triggers. It ran eleven waves.

The fresh-context audit returns **major**. Every spec gate is green at `38e04853` and every gate sampled fails when its fix is reverted (eleven source mutations, eleven red runs). The compiler, loader, layer composition, render transaction and trigger hook hold on production paths. One high finding is open: the role carriers have no production delivery. No rule is role-scoped, so the render emits zero carriers, and no agent definition preloads one even if it did. The design names carriers as the certified deterministic vehicle for scoped `must` rules. Six medium findings cover the managed ignore block, host-fact coverage, a duplicated host-fact model, the missing `RULE-009` compile refusal, this repository's unsynced checkout and conduct verification.

## What the audit found

**The compile, load and compose work holds.** W01 refuses traversal, absolute, include and credential-shaped input at the loader, and removing the leak refusal at `src/eawf/platform/rules/loader.py:230` reds the gate. W02's duplicate-owner and authority-widening refusals fire, and dropping the canonical sort at `src/eawf/platform/rules/compile.py:474` reds the order-invariance test. W04's committed-input refusal at `src/eawf/platform/rules/compose.py:285` keeps the workspace layer out of the card, and removing it reds the gate. The workspace layer reaches production through `load_rule_layers` from `compile_rule_graph`.

**The render transaction is wired and atomic.** `eawf sync`, `eawf profile enable`, the doctor repair and the daemon doctor sync all call `render_rule_projections` or `refresh_rule_projections` when `.ea/rules.yaml` exists, and otherwise fall back to the legacy profile renderer. Replacing `_restore(prior)` with a no-op reds the interrupted-write test. For this repository the card renders 12,314 B and the policy projection 27,921 B against the 32,768 B certified Codex cap, leaving 4,847 B of policy headroom. W07's Claude shim imports only `AGENTS.override.md`. That satisfies `RULE-131`, because the policy projection is a superset of the card and the same transaction writes both. The view-staleness refusal reds when removed.

**What reaches the model is thinner than what compiles.** The committed card now carries 34 constitution rules, and 7 of the 34 old numbered rules are no longer among them: #9 f-strings and #10 `uv run` are retrievable `must` rules, and #21 to #24 and #31 are steering `should` rules. The typed decision behind the design ratifies this split, but this checkout has never been synced. `AGENTS.override.md` and the views are absent, `CLAUDE.md` is still the legacy `@AGENTS.md`, and so sessions here read only the card. OpenCode reads only the card by record, so no non-constitution `must` rule ever reaches it. The compiler does not implement `RULE-009`'s refusal. The renderer puts every `must` rule whole into the policy file instead, and W05's delivery test exempts the craft and conduct modules.

**The host-fact record certifies one cap and the rest is silent.** Only Codex's project-document cap is certified. `CertifiedCap.uncertified` is computed and never read, so Claude, which reads the policy file through its shim, is held to Codex's cap without any signal. The manifest declares bytes but no tokens (`RULE-124`). The record lacks the cap scope and the four delivery facts `RULE-126` adds. No certified fact carries a re-measure or stale marker (`CONDUCT-055`). The same four facts also have a second typed home in `src/eawf/kernel/runtime/certification.py:174`.

**Carriers, staleness and triggers.** W08's staleness hook is live: every Claude session in a repository with a rule source replans the projections (about 0.5 s) and reports once per session. In this checkout it reports 11 stale targets. A compile or render error in that hook reaches the session context as a raw Python `repr`. The carrier renderer runs, but with no role-scoped rule it emits nothing, and no agent frontmatter names a carrier. W11 hooks `fire_practice_triggers` into `run_skill`, and removing the call reds the gate. The trigger bodies match the real `coordination_report`, `verification_report` and `user_question` shapes. Its three decision points (dispatch, choice, report) follow the design file, not the brief's plan, dispatch and close. All 47 conduct obligations are recorded as verified by `review`, although the design map assigns structural or registered-check verification to about seventeen of them. Deviations reach the machine-local store through `append_envelope`, and only the three trigger obligations can produce one.

### Codex project-document delivery

The host fact is right and this repository is within budget. Codex's documented discovery takes at most one instruction file per directory, from the project root down to the working directory. In each directory `AGENTS.override.md` wins over `AGENTS.md`, and `project_doc_max_bytes` (32 KiB by default) caps the concatenated total. The shipped record says the same in its comment ("The policy projection replaces the card when present", `src/eawf/platform/rules/data/host_facts.yaml:33-34`). The cap code checks each projection on its own: `smallest_certified_cap` computes one cap per projection kind (`src/eawf/platform/rules/host_facts.py:137`), and the doctor measures each file separately. A synced Codex session reads only `AGENTS.override.md`, 27,921 B of 32,768 B (4,847 B headroom). An unsynced checkout or a worktree reads `AGENTS.md`, 23,127 B (9,641 B headroom). This repository has no nested `AGENTS*.md`. Adding the two sizes (51,068 B) would be the wrong model. The only defect here is the misleading `reads` wording (N6).
