# P35-I03 evaluation audit

## Summary

Iter P35-I03 set out to ship the skill catalog, measurement, notices and quality homes: a closed catalog of twenty skills with typed grammar and outputs, six-slot skill pages, refreshed envelope evaluations, five token classes with a price source on every Run, a local session-history sweep, non-blocking budget notices, one prompt-budget ceiling with a statusline, a runtime-set conflict guard and managed config blocks, MCP grant by intersection with an isolated managed Claude child, the test-tier ladder, jury calibration and telemetry contracts, a requirement trace census, and repairs to the P32 and P34 gates. It ran fifteen waves (`7f485f8e` to `c9d179ca`, base `adb438d3`).

The fresh-context audit returns **major**. Every spec gate is green at `00ca3eee` (730 passed, 2 skipped over the seventeen gate files), and nine gates sampled by source mutation each went red. Two findings are high. W04 broke cross-vendor spawn-result parity: `tests/integration/test_cross_vendor_parity.py` passes at the iter base and fails at head, and the main CI pytest lane collects it. W10 ships `red_to_green_finding` with no production caller, so the criterion's "at the task boundary" clause holds only in a unit test. A third CI red comes from the committed I02 audit artifact, which the strict prose gate rejects. Six medium findings cover the two budget limits, the partial `eu_capture` producer, retired skills still runnable through `eawf flow run`, unpriced default models, the untyped `memory` question with thin evaluation goldens, and partial managed-run isolation.
