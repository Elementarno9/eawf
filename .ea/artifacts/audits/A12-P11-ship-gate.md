## Aggregate verdict

**pass.** The operator's two requests both land: (1) `/prep` now
defers to `planning.auto_plan` and enters plan mode by default with
a DAG proposal, escapable via config flag or `--auto-plan` arg; (2)
every core skill body and `/flow` itself routes discrete decisions
through `AskUserQuestion`, with `flow.auto_accept.<stage>` per-stage
overrides for unattended runs. The skill prompts (which the user
will re-emit into the CC plugin tree via `eawf plugin package
claude --force`) carry the new instructions verbatim.

## Out of scope (deferred to P12+)

- Per-skill front-matter `auto_plan` / `auto_accept` overrides — the
  v0.1 SkillSpec frontmatter has no such field; an additive change
  to the Pydantic skill schema can land in a later phase when there
  is a concrete use case for per-skill overrides above the config
  gate.
- A Click-level `--auto-plan` / `--auto-accept` flag on the actual
  `eawf skill prep` / `eawf skill flow` engine entry points — the
  slash invocation is interpreted by the agent harness, which reads
  the SKILL.md guidance and the config; the Python skill engine
  retains its existing `approval=ask` arg.
- Telemetry on auto-accept usage (how often operators opt into
  `--auto-accept=ship`) — folds into the broader B012 telemetry
  backlog item.
