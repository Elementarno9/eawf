# v0.6.0 re-close runbook (P30 phase re-close via P30-I21-W22)

## Summary

P30 re-closes as v0.6.0 once the I23 max-hardening iter is audited and closed. The re-close rides the single phase-close bookkeeping commit on P30-I21-W22 — the ONLY remaining PENDING wave in the repo — with the release annotation as its own parenthesised group so the tag workflow's extraction regex matches [1][2]. Windows support ships de-scoped: the win32 SID-verify path has never run a real win32 round-trip, so the release notes mark Windows experimental and real-host validation moves to the P31 daemon re-architecture remainder per D-WINDOWS-DESCOPE [3].

## Drafted phase-close subject

```
[P30] state: close iter + phase (audit=A-P30-I22-ship) (release=v0.6.0)
```

The annotation is a standalone paren group — never fused into the audit group (the BL-1 shape `(audit=..., release=v0.6.0)` hard-rejects in `tools/commit_prefix_lint.py` and would silently miss the workflow extraction regex `\(release=(v\d+\.\d+\.\d+(?:a\d+|b\d+|rc\d+)?)\)` [1][2]).

## Ordering (operator-confirmed at the ship gate)

1. I23 audit (`/audit P30-I23`) passes; every I23 wave CLOSED.
2. `eawf iter close P30-I23 --audit <audit-id>` (the ODR gate now blocks per `verify.odr_blocking: true`).
3. Re-open surface: P30-I21-W22 claim; run its two gates (release-annotation dry-run + CHANGELOG structural).
4. The phase-close commit carries the drafted subject verbatim; push; PR review pass; rebase-merge (never squash).
5. Post-merge `.github/workflows/phase-release.yaml` extracts `v0.6.0`, tags the merge commit, publishes notes; publish gates on green CI + tool-install smoke.

## Windows de-scope (D-WINDOWS-DESCOPE)

v0.6.0 release notes mark Windows support experimental/de-scoped; the win32 SID-verify path awaits real-host validation in P31 (ZD-R10 / harm-register H12).
