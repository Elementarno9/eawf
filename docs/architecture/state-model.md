# State model

*Strict-Pydantic generation document and ledgers for workspaces, projects and lifecycle entities.*

## The tree and its generations

`eawf init` creates a native tree: a repo-owned `.ea/` directory whose state lives in a selected generation rather than in a top-level `state.json`.

```text
.ea/
  generations/
    EPOCH2_ACTIVE.json        # the epoch marker naming the active generation
    selected.json             # the selected generation and its digests
    <generation-id>/
      state.json              # the generation document
      ledger/<collection>.jsonl
      history/change.jsonl
      local/                  # machine-local status projection, never committed
```

A reader resolves the tree's authority from the opt-in declaration and the marker (`eawf.kernel.state.epoch2.authority.resolve_authority`), then reads the selected generation's document with its machine-local status projection laid over (`eawf.kernel.store.compaction.read_document`). The state path follows the precedence `EA_STATE`, then `-w` / `--workspace`, then the nearest `.ea/` above the working directory (`eawf.kernel.state.resolve`).

Invariants:

- Every entity has one owning tree, and every durable reference to it is a qualified `eawf://` URN.
- The daemon is the only writer of the document, its ledgers and its history; a CLI mutation proxies to it.
- `eawf validate` checks the selected generation document (`eawf.kernel.validate.epoch2.validate_generation`).

## Containment and orthogonal entities

```text
Workspace
  └─ Project
      └─ Track
          └─ Milestone
              └─ Batch          # one repository's integration unit
                  └─ Task
```

A Run is one execution episode against one scope of that tree. A Release packages accepted Milestones across Tracks and sits beside the chain. A PlanRevision is a document about entities that do not exist yet: it carries one Milestone, its Batches and their Tasks until an apply materialises them. Cross-cutting records (Campaign, PendingAction, OpenQuestion, Decision, Hypothesis, Audit, Incident, Evidence, Receipt, Artifact, Memory) live in their own collections.

## The generation document

The document is one JSON object. Its keys are:

| Key | Type | Required | Notes |
|---|---|---:|---|
| `schema_version` | literal `"2"` | yes | the native document generation |
| `canonical_sequence` | integer | no | the committed sequence the ledgers advance |
| `<collection>` | map[key, row] | no | one object of rows per `Epoch2Collection` member, keyed by public key |

Every other top-level key is refused. A row of a modelled collection is a record of that collection's native model, or the wrapper the epoch-2 cutover wrote around an imported record (`status`, `recorded_at`, `payload`, and no `urn`). The bundled `src/eawf/schemas/state.schema.json` is this shape as JSON Schema, generated by `eawf.platform.docs.autogen.generate_state_schema`.

All models use `extra="forbid"`, sequences are tuples, timestamps are UTC ISO-8601, and relationships are typed URNs, so a field that promises a Milestone cannot hold a Batch.

## Residency: document, ledger, history

A record stays in the document while it is in flight. Once it reaches a terminal status (for a Task, `COMPLETED`, `CANCELLED` or `FAILED`) it moves to its collection's ledger under `ledger/`, and a reference resolves against both tiers. Ledgers are append-only: a correction is a new row that supersedes an earlier one, never a rewrite. `history/change.jsonl` records each committed change. In-flight status sits in the generation's `local/` projection so a status flip does not dirty the committed document.

## Key grammar

```text
Workspace / Project code:  ^[A-Z][A-Z0-9_-]{1,15}$     # e.g. EAWF, AO-SERVER
Track:                     TRK-<symbol>                 # e.g. TRK-EAWF-CORE
Milestone:                 MLS-####
Batch:                     BAT-####
Task:                      <PROJECT>-####               # e.g. EAWF-0042
Run:                       RUN-########
PlanRevision:              PRV-####
Release:                   REL-<version>                # e.g. REL-0.7.0
Hypothesis:                H<NN>-<NN>
```

The ordinal families and their widths are `KEY_ORDINAL_FAMILIES` in `src/eawf/kernel/identity/keys.py`. Keys are immutable.

## Estimation model

```text
1 EU = 30 minutes active operator + agent session time
```

Estimates and actuals are their own collections with append-only ledgers: never overwrite prior measured session time. Calibration uses completed scopes only; interrupted, blocked, abandoned, failed and superseded scopes feed risk and fallback statistics.

## Large entity handling

The document stores **index fields and summaries**, not full long-form documents. Long-form details (research briefs, plan specs, long hypothesis rationale, full audit metric tables, incident timelines) live as artifacts under `.ea/artifacts/` and are referenced by artifact ID + URN. Markdown artifacts use the standard chassis: `Summary`, `References`, `Provenance`, and `Scrub`. Local drafts under `.ea/local/` carry an `eawf-template` sentinel and lose it on promotion.

Suggested thresholds:

- `title`: 72 chars
- `summary`: 500 chars
- `details`: 2,000 chars max inline, then artifact required
- metric tables, long logs, and transcripts: artifact required

## URN namespace

Lifecycle entities use the qualified URN `eawf://<workspace>/<project>/<repository-or-_>/<kind>/<key>`; store records, artifacts, blobs and version-control objects use `urn:eawf:v1:<kind>:<owner>/...` (source of truth: `URN_KINDS` in `src/eawf/kernel/state/urn.py`). See `docs/reference/urn-namespace.md` for the full specification.

## Validation invariants

- Every top-level key is `schema_version`, `canonical_sequence` or an `Epoch2Collection` member, and every collection holds an object of rows.
- Every native row validates against its collection's model.
- A Batch names a Milestone, and a placed Task names a Batch, that the document or its ledger holds.
- A Task is dispatchable only from `PLANNED`; a `DRAFT` Task carries no Batch and no criteria.
- Artifact file refs exist or are explicitly external.
- Secret / env refs use `${ENV:NAME}` and never store values.
